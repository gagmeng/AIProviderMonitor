# AI Provider Monitor

当前版本：**1.6.1**。开发环境要求 Node.js **22.12+**；桌面运行时使用 Electron **45.2.3**。

本次七项 P1 缺陷修复（检测判定、配置变更、损坏保护、稀疏备份、凭据脱敏、编辑会话隔离、多通道告警交付）见 [v1.6.1 修改摘要与发布说明](RELEASE_NOTES_1.6.1.md)，修复实现与各项验证见 [七项 P1 修复记录](P1_FIXES_1.6.0_2026-11-10.md)，原始复现与剩余 P2/P3 见 [v1.6.0 系统审查](PROJECT_REVIEW_1.6.0_2026-11-10.md)。服务商模板、克隆、SLO 与桌面界面改进见 [v1.6.0 修改摘要与发布说明](RELEASE_NOTES_1.6.0.md)，缺陷修复对照、SLO 定义和测试记录见 [实施与验收说明](IMPLEMENTATION_1.6.0.md)，设计方向见 [桌面界面实施记录](UNSLOP_UI_2026-11-10.md)，各页面交互问题与处理见 [UI 检查记录](UI_REVIEW_2026-11-10.md)。[GitHub 正式版下载](https://github.com/gagmeng/AIProviderMonitor/releases/tag/v1.6.1)。

一款基于 **Electron** 的 AI 服务商（AI Provider）状态与可用模型监控桌面应用。界面采用中性色、清晰的数据层级及浅色/深色主题，支持按服务商自定义周期自动轮循检测连接状态与模型可用性，并在**模型发生变动**时通过微信、QQ、钉钉、Telegram、飞书、Slack、Server酱或自定义 Webhook 推送通知。

适用于企业内部 AI 网关、OpenAI 兼容中转站、本地推理服务（vLLM / Ollama / One-API 等）的可用性巡检与模型变更监控。

## 系统功能

### 1. 服务商管理

| 功能 | 说明 |
|------|------|
| 新增 / 编辑 | 基础表单：模板、名称、URL、API Key、周期、变动上报；高级表单：鉴权、能力、断言、维护、代理、SLO 等 |
| 服务商模板 | OpenAI、OpenAI 兼容、vLLM、LM Studio、原生 Ollama、自定义端点 |
| 一键克隆 | 复制配置并生成唯一名称与 ID；新副本停用，排除 API Key、自定义请求头及代理，不复制检测历史与告警状态 |
| 测试连接 | 编辑弹窗一键试测：不保存直接跑一轮检测，就地显示状态 / 延迟 / 模型可用数；编辑已有服务商时自动沿用已存密钥 |
| 删除 | 单个删除（带确认弹窗） |
| 全选 / 取消全选 | 三态勾选框操作当前筛选结果 |
| 批量删除 | 多选后批量删除，带确认提示 |
| 批量手动检测 | 对选中服务商立即触发一轮检测 |
| 搜索 | 按名称 / URL / 备注 实时过滤 |
| 分组折叠视图 | 按分组分节显示（未分组垫底），节头显示在线数、可折叠；拖拽排序在扁平视图下进行 |
| 拖拽排序 | 无筛选的扁平列表中按行首手柄拖拽调整显示顺序，落盘持久化 |
| 行内信息 | 周期列下方显示下次检测时间；最近检测列下方显示 24h 时间加权可用率（绿 ≥99% / 橙 ≥90% / 红） |
| 启用开关 | 临时停用某个服务商的周期轮循（保留配置） |
| API Key 保护 | 界面仅显示掩码（`sk-R****pB9d`），编辑留空表示不修改 |

每个 AI Provider 由以下字段构成：

| 字段 | 必填 | 说明 |
|------|------|------|
| 供应商名称 | ✅ | 自定义显示名称 |
| URL | ✅ | API 根地址（自动补全 `https://`，去除尾部 `/`），如 `https://api.openai.com` |
| API Key | ❌ | Bearer Token，用于 `/v1/models` 与 `/v1/chat/completions` 鉴权 |
| 轮循周期 | ✅ | 数值 + 单位（秒/分/时/天/周/月/年，最低 5 秒），到达周期自动检测 |
| 模型变化上报 | ✅ | 开启后，模型数量或可用状态变化时触发通知 |
| 备注 | ❌ | 自由文本 |

### 2. 轮循检测引擎

- **连接状态**：请求 `/v1/models`，判定 在线 / 异常 / 离线 / 鉴权失败 四态，并记录延迟（ms）
- **模型列表**：兼容 OpenAI（`data[].id`）、Ollama（`models[].name`）、纯数组三种响应格式
- **模型可用性**：对每个模型发送最小 `chat/completions` 请求（`max_tokens=1`），默认严格模式要求成功 JSON 响应并通过已配置断言；兼容可达性模式可接受部分 400/413/422，但不会绕过断言或接受配额错误；404 / 401 / 403 / 429 / 5xx / 超时分别给出具体失败原因
- **状态语义**：

| 状态 | 判定条件 | 含义 |
|------|----------|------|
| 🟢 在线 up | 至少 1 个模型可用 | 服务正常 |
| 🟠 异常 degraded | 连接成功但所有模型不可用 | 服务在但模型全挂 |
| 🔴 离线 down | 连接失败（网络/超时/DNS） | 服务不可达 |
| 🟣 鉴权失败 authfail | API Key 无效（401/403） | 需更换密钥，不计入普通离线 |

- 每轮探测数量默认上限 20 个，超出部分标记为「未探测」，避免大模型列表拖慢周期

### 3. 变动通知

当某服务商「模型变化上报」开启，且本轮检测的 **可用模型集合** 发生确认变动（新增可用 / 失去可用）时，向已启用的通道推送变化详情：

- **微信**：企业微信群机器人 Webhook
- **QQ**：OneBot v11 HTTP 服务（NapCat / Lagrange / go-cqhttp），支持私聊与群聊、access_token 鉴权
- **钉钉**：自定义群机器人 Webhook，支持官方**加签**安全设置
- **Telegram**：Bot API `sendMessage`，可自定义 API 反代地址
- **飞书**：自定义机器人 Webhook，支持可选加签
- **Slack**：Incoming Webhook
- **Server酱**：`sctapi.ftqq.com` / `sc.ftqq.com`
- **自定义 Webhook**：任意 HTTP(S) 地址，JSON 模板支持 `{{text}}` `{{name}}` `{{status}}` `{{url}}` `{{time}}`

八个通道相互独立、可同时开启，任一通道失败不影响其它通道；通知页「通道健康」面板逐通道显示最近成功 / 失败状态。**某通道连续失败 3 次（此后每再败 5 次）会自动转成一条未读告警并弹托盘气泡**——避免「告警发不出去」只有日志一行、不看界面无从发现。服务商编辑弹窗里的「通知通道路由」可把该服务商的告警限定到指定通道，不勾选则广播全部已启用通道。

### 4. 仪表盘

- 在线 / 异常 / 离线 / 鉴权失败 / 可用模型总数 五张统计卡
- 「最近检测」活动流（最近 8 条，含状态、可用率、错误信息）
- **单击任意条目**打开该服务商状态详情，也可用 Tab 聚焦后按 Enter 打开
- **持续三步引导**：在三步完成或手动关闭前，仪表盘保留「新增服务商 → 配置通知 → 首轮检测」向导，每步带直达按钮与完成态

### 5. 服务商状态详情

- 状态横幅：四态配色 + 可用率 + 延迟
- 元信息：URL、API Key 掩码、轮循周期、最近检测时间、备注、连接错误
- **近 90 天可用率色条**：每天一格（绿 ≥99% / 橙 ≥90% / 红 / 灰无数据），status-page 风格，悬浮显示当日可用率
- **近 24 小时走势图**：可用率（绿）+ 平均延迟（蓝）双轴折线，区分「刚好这轮慢」和「一直慢」
- 可用模型标签云（点击复制模型名，附 24h 可用率徽标）
- 不可用 / 未探测列表：**每个模型旁显示具体失败原因**（模型不存在 404 / 鉴权失败 / 速率受限 / 服务端错误 / 超时 / 未探测）
- **双击服务商列表行任意位置**即可打开详情

### 6. 日志

- 运行日志实时滚动（新增服务商、检测开始/完成、通知成功/失败、配置变更等）
- 按级别着色（info / warn / error / debug）
- **级别下拉过滤 + 按服务商过滤**（日志行内含 `[服务商名]` 标记）
- **日志文件管理**：列表显示磁盘日志文件（大小 / 时间），可打开目录或删除单个文件（仅接受本工具命名规则的文件名）
- 同时落盘到数据目录 `logs/aipm-YYYYMMDD.log`

### 7. 系统集成

- 系统托盘常驻：显示主界面 / 立即检测全部 / 退出；关闭窗口仅隐藏到托盘
- **托盘菜单逐服务商状态**：右键菜单直接列出每个服务商的状态与可用模型数（超过 15 个折叠汇总），点击直达详情
- **全局暂停检测**：托盘勾选项 / 仪表盘按钮一键暂停全部自动轮循，手动检测不受影响；恢复时错过周期的立即补检
- **托盘图标状态染色**：绿 = 全部在线，橙 = 有异常，红 = 有离线 / 鉴权失败，一眼看出整体健康度
- 单实例锁：重复启动自动唤起已有窗口
- 快捷键：`Ctrl+R` 立即检测全部、`F5` 重载界面、`F12` 开发者工具、`Ctrl+Q` 退出

### 8. v1.2.0 新增能力

- **鉴权失败独立状态**：401/403 单列紫色状态，告警与统计与普通离线区分
- **维护窗口**：按服务商设置免告警时段（可跨零点），窗口内故障不推送
- **TLS 校验控制**：全局 + 按服务商（跟随/始终校验/跳过），支持自签证书内网
- **探测调优**：并发池（5–10）、请求抖动、超上限轮询覆盖，避免请求突发
- **单模型历史**：详情页可用模型附 24h 可用率徽标
- **未读告警**：托盘 tooltip 计数 + 仪表盘徽标，打开列表逐条或全部确认
- **邮件日报**：SMTP 每日定时发送可用率日报（依赖 `nodemailer`）
- **全局快捷键**：默认 `CommandOrCtrl+Alt+M` 显示/隐藏主界面，可自定义
- **托盘气泡**：新告警弹气泡（5 分钟节流）
- **中英双语**：设置页一键切换（操作指南暂仅中文）
- **自动检查更新**：启动约 30 秒静默检查（需安装 `electron-updater` 并配置发布源，否则跳过）

### 9. v1.3.0

- 月/年轮循不再因定时器上限变成约每秒检测一次
- 模型变动只在集合真正变化时上报一次，状态翻转不再绕过故障消抖
- 配置损坏时保留原文件，禁止用空库覆盖
- 跨源重定向不再携带 API Key；通知代理遵循「代理已启用」
- 菜单「检查更新」会提示结果；启动检查保持静默
- 统计单独计入鉴权失败；邮件 TLS 与探测 TLS 分开
- 日报错过发送分钟会在当天补发一次

同版本还包含：

- Provider 支持自定义模型列表路径、Bearer / 自定义 Header / 无鉴权、自定义请求头。
- 支持 Chat / Embeddings / Completions 能力矩阵探测，以及包含文本 / JSON 路径响应断言。
- 记录单模型探测延迟并汇总平均值、P95；服务商列表可查看下一次计划检测时间。
- 请求重试遵循 `Retry-After`，连续失败达到阈值后自动熔断，手动检测仍可绕过熔断。
- 支持按 Provider 路由通知通道，并按日期、星期和每日时段组合维护窗口。
- 敏感全局配置与 Provider 自定义请求头不再通过公共状态明文下发到渲染进程。
- 支持正则模型忽略规则；可配置配额查询端点、剩余额度 JSON 路径和低配额告警阈值。
- 可选 OpenAI 兼容流式性能探测，记录首 Token 延迟与估算吞吐（仅额外探测一个可用模型）。
- 未读告警不再因窗口获得焦点而自动消失，需点击未读徽标显式确认。

### 10. v1.4.0

- **安全与校验收口**：导入 / 合并还原与手工新增走同一套 Schema 校验，坏正则、非 HTTP(S) 地址、未知通知通道在入口即拦下；备份覆盖还原的 global 一律经过归一化（数值钳位、时间格式校验、未知键丢弃）。
- **密钥全生命周期**：设置页所有敏感项与 Provider 的 API Key / 自定义请求头 / 专用代理均可从界面清除（留空仍表示不修改）；Provider 代理地址在状态快照中掩码下发。
- **延迟劣化告警**：服务在线但连接延迟连续 N 轮超过阈值时推送（阈值、轮数可配，受静默 / 维护窗口 / 冷却约束）。
- **故障升级提醒**：故障持续指定分钟数仍未恢复时重复推送，避免长时间故障只提醒一次。
- **未读告警逐条确认**：点击未读徽标打开列表，可逐条确认或一键全部确认。
- **SLA 报表**：统计页与导出报告（HTML / CSV / Excel）新增故障次数、MTTR、最长故障三项指标。
- **通知通道健康面板**：通知页实时展示 8 个通道最近一次推送成功 / 失败时间与连续失败次数；面板区分「未使用」「配置不完整」「已启用 · 待发送」「正常」「连续失败」五态，健康记录随数据目录持久化（`notify-health.json`），重启后不丢，点「测试」发送同样计入并立即刷新面板。
- **日报去重标记持久化**：`lastReportDay` 纳入已知键白名单并做 `YYYY-MM-DD` 校验，修改任意设置后不会导致同一天重复发送日报；该键仅由主进程维护，渲染层写入会被 `global:set` 拒绝。
- **凭据清除联动**：清除某通道的 Webhook / Token / Key 时同步重置该通道健康记录，避免新配置沿用旧的绿灯或红灯。
- **批量编辑**：勾选多个服务商后可批量修改轮循周期、变动上报开关、分组与代理设置。
- **API Key 显隐与复制**：编辑弹窗支持眼睛图标切换明文、一键复制。
- 导出默认不再包含 API Key，勾选包含密钥时需二次确认；备份包含密钥时同样确认。

### 13. v1.6.0：SLO、时间加权可用率与错误预算

在「设置 → SLO 目标」设置全局目标（90–100%，默认 99.9%）与滚动窗口（1–90 天，常用 7 / 30 / 90，默认 30）。服务商高级配置中可覆盖目标，留空继承全局。

「统计」上方时间筛选控制历史明细和趋势；SLO 区域始终使用独立的配置窗口，并在标题显示实际天数。详情窗口也展示该服务商的滚动 SLO。导出 SLO 报告使用同一窗口，HTML / CSV / Excel 包含时间加权可用率、覆盖率、允许/实际故障时长、未知时长、剩余预算、预算使用率、已恢复 MTTR 和当前故障。

- 每个检测状态向后覆盖到下个样本，最长延续 **两个计划周期**；超过有效期的区间记为未知。应用未运行、暂停或停用后，已有样本仍受此有效期限制，之后不推断为在线或故障。
- 时间加权可用率 = 在线时长 ÷ 已观测时长；覆盖率 = 已观测时长 ÷ 完整窗口时长。`degraded`、`down`、`authfail` 均记为故障；维护窗口仅抑制通知，故障仍纳入统计。
- 允许故障时长 = 完整窗口 × (1 − SLO 目标)。剩余错误预算 = 允许故障时长 − 已知故障时长，可为负值。目标 100% 时允许故障为零。
- 已知故障超过预算显示「已超预算」；未超过但含未知时间显示「数据不足」；覆盖完整且预算未耗尽才显示「已达标」。新安装或历史保留不足不会直接显示达标。
- 总体指标按**服务商时间**累计，多服务商的未知时长和预算可能超过单个日历窗口。副本和停用服务商仍可在报告中显示历史与覆盖率，不能凭停用推断在线。
- 单模型徽标、每日色条和趋势图保留**样本可用率**口径；不将其当作 SLO。旧历史没有计划周期时，使用样本间隔中位数估算（最多一天；只有单样本时默认 5 分钟），历史不可重建的精度通过未知时段体现。
- 历史默认保留 90 天，已有用户的保留配置沿用；保留期短于 SLO 窗口时设置页显示提示。MTTR 仅平均已经恢复的事件，当前未恢复故障另列。

统计页默认只统计当前配置中的服务商，历史采样不会重新创建已不在配置中的服务商。需要查阅旧记录时，选择「统计范围 → 包含历史服务商」，概览、趋势和导出一起切换，并标注「历史记录」。

快捷键以 `Ctrl` + `Alt` + `M` 按键块显示，点击组合后直接按下新组合录制，支持 Esc 取消和恢复默认。

通知恢复/模型变动在静默、维护或发送失败后持久保留，按通道记录成功交付，30 秒起退避重试、最大间隔 5 分钟；没有启用通道也不会假定已发送。配置恢复后可自然补发。启动及跨日执行自动备份和历史清理，不依赖每日重启。

### 14. v1.6.1：七项 P1 缺陷修复

本版为 v1.6.0 系统审查结论的修复版本，不含新功能与界面改版。逐项复现材料与原始结论见 [v1.6.0 系统审查](PROJECT_REVIEW_1.6.0_2026-11-10.md)，实现与验证记录见 [七项 P1 修复记录](P1_FIXES_1.6.0_2026-11-10.md)。

- **检测判定（D01）**：HTTP 200 不等于推理成功。严格模式按 chat / completions / embeddings / custom 校验最小有效结果，并先识别 `error`、非空 `errors`、`success:false`、`ok:false` 等业务错误，再执行用户断言；空对象、空 `choices`、空向量判失败，工具调用、推理内容与合法的长度截断仍通过。响应凭据同步脱敏。
- **配置变更事务（D02）**：新增检测配置指纹，覆盖 URL、凭据、鉴权、模型路径、探测方式与请求体、断言、忽略规则、配额、流式测量、代理、TLS、各类超时及影响请求的全局网络设置。编辑、批量、导入、备份还原与全局设置在保存事务内重置运行态、取消在途检测并补检；完成时校验代次与指纹，旧结果不写状态、历史和告警，迟到回执丢弃；保存失败整体回滚且不打断运行中的检测，改名备注不废弃正常结果。
- **损坏配置保护（D03）**：`providers` 非数组、数组内混入非对象、`global` 非对象时进入只读恢复流程，保留原文件并尝试建立 `.corrupt-*` 副本；新安装与合法空数组照常加载。
- **稀疏备份合并（D07）**：按备份中显式出现的字段生成补丁，未提供的启用状态、探测方式、维护、独立 SLO、通知路由、能力矩阵与凭据继续保留；显式 `false` / `null` / 空数组仍可覆盖，运行态不从备份合并。
- **凭据脱敏（D08）**：统一脱敏 URL userinfo 与 URL / 模型列表 / 探测 / 配额路径中的敏感查询参数（含大小写、重复参数与编码参数名）。公共状态、日志（含磁盘文件）、告警文案、自定义 Webhook `{{url}}`、检测错误与测试结果均用脱敏值，实际请求仍用原配置；默认导出与克隆移除 URL 凭据，完整导出保留。表单以 `***` 显示，保留掩码或改普通参数沿用原值，删除参数或填新值即替换。
- **编辑会话隔离（D14）**：弹窗、密钥回显、连接测试与保存分别编号，回调校验会话、服务商 ID、表单修订与内容指纹；A 的延迟回显或测试结果不会落到 B，途中的手动输入与清空不被旧值覆盖。
- **告警交付（D15）**：故障生命周期与消息交付分离，每次故障有独立 incident ID，按通道记录最后事件与顺序；部分通道恢复失败后再次故障会建立新事件，已恢复的通道同样收到新故障；成功通道重试时跳过，迟到回执不覆盖新状态，旧版全局状态可平滑迁移。同一服务商的通知按顺序发送。

## 实现方案

### 检测流水线（detector.js）

```
detect(provider)
  ├─ GET  {base}/v1/models          ← Bearer 鉴权，20s 超时
  │    ├─ 失败 → status=down, error="连接失败: ..."
  │    └─ 成功 → 提取模型列表（OpenAI/Ollama/数组格式自适应）
  │
  └─ 对稳定排序后的前 probeLimit(=20) 个模型并行 POST /v1/chat/completions
       body: { model, messages:[{role:"user",content:"ping"}], max_tokens:1 }
       ├─ 2xx + JSON + 断言通过  → 可用
       ├─ 400 / 413 / 422        → 严格模式失败；仅兼容模式且无断言、无配额错误时可达
       ├─ 404                    → 不可用「模型不存在」
       ├─ 401 / 403              → 不可用「鉴权失败或无权限」
       ├─ 429                    → 不可用「请求速率受限」
       ├─ 5xx                    → 不可用「服务端错误」
       ├─ 超时                    → 不可用「探测请求超时」
       └─ 超出上限                → 未探测（不计入不可用）
```

### 变动判定与通知触发（main.js）

```
applyResult(provider, result):
  prev = snapshot(provider)                    // {status, modelsAvailable}
  diff = diffBaseline(已确认可用基线, 本轮可用/不可用/未探测/初始未知目录)
  modelChanged = diff.added.length > 0 || diff.lost.length > 0
  decision = alerts.evaluate(全局策略, provider, prev, diff)
  dispatchAlerts(decision.alerts)              // 静默/维护保留待发送事件
  alerts.noteDelivery(provider, event, result) // 成功交付后确认，失败重试
```

通知消息示例：

```
【AI Provider 模型变动】
服务商：Provider B
状态：up → degraded　可用模型 0/3
失去可用：gpt-5.6-terra, gpt-5.6-luna
时间：2026/9/11 10:56:03
```

### 通知通道实现（notifier.js）

| 通道 | 端点 | 请求体 | 鉴权 |
|------|------|--------|------|
| 企业微信 | 群机器人 Webhook | `{ msgtype:"text", text:{ content } }` | key in URL |
| QQ (OneBot v11) | `{base}/send_private_msg` 或 `/send_group_msg` | `{ user_id \| group_id, message }` | `Authorization: Bearer <token>`；校验响应 `retcode===0` |
| 钉钉 | 自定义机器人 Webhook | `{ msgtype:"text", text:{ content } }` | 加签：`timestamp + "\n" + secret` 的 HMAC-SHA256 Base64 附到 URL；校验响应 `errcode===0` |
| Telegram | `{apiBase}/bot{token}/sendMessage` | `{ chat_id, text }` | token in URL |
| 飞书 | 自定义机器人 Webhook | `{ msg_type:"text", content:{ text } }` | 可选加签 `timestamp + "\n" + secret`；校验响应 `code===0` |
| Slack | Incoming Webhook | `{ text }` | URL 自带凭据；非 2xx 视为失败 |
| Server酱 | `sctapi.ftqq.com/{key}.send`（`SCT` 开头）或 `sc.ftqq.com/{key}.send` | 表单 `title` + `desp` | key in URL |
| 自定义 | 用户填写的任意 HTTP(S) URL | `{ text }`，模板与请求头可覆盖 | 由自定义请求头决定 |

`channelEnabled(globalCfg, ch)` 判定「开关打开 **且** 凭据/目标齐全」，只有为真的通道才参与广播；单个通道抛错不影响其它通道，错误计入该通道健康记录。

**通道健康（`notify-health.json`）**：每次真实发送（含「测试」按钮）调用 `noteResult(channel, ok, err)`，记录 `{ fails, lastOkAt, lastFailAt, lastError }`。渲染层拿到的是 `selfmon.notifyHealth` 深拷贝，按「开关 + 配置完整性 + 记录」渲染五态：

| 状态 | 条件 | 展示 |
| --- | --- | --- |
| 未使用 | 通道开关关闭 | 灰点 + `未使用` |
| 配置不完整 | 开关打开但缺 Webhook / Token / 目标 | 灰点 + `配置不完整` |
| 已启用 · 待发送 | 开关打开且配置完整，但还没有发送记录 | 灰点 + `已启用 · 待发送` |
| 正常 | 配置完整且 `lastOkAt` 存在、`fails === 0` | 绿点 + `正常 · 最后成功 {t}` |
| 连续失败 | 配置完整且 `fails > 0` | 红点 + `连续失败 {n} 次 · {t}`，悬停显示 `lastError` |

凭据被清除时（`global:clearSecrets`）对应通道的健康记录同步重置，避免新凭据沿用旧结论。

### 调度器设计（scheduler.js）

- **每 Provider 一个绝对定时器**：周期变更即时重置，避免漂移；执行完一轮后从最新配置重新计算下轮间隔
- **并发池**：全局默认 4 并发（可配 1–16），队列 + 去重（同一 Provider 检测中不接受重复手动触发）
- **停用语义**：`enabled=false` 清除定时器、自动队列并取消在途检测；保留配置，重新启用后恢复

### 数据持久化（store.js）

- 存储位置：`%APPDATA%/ai-provider-monitor/providers.json`
  - 便携版（Portable）：自动切换到 exe 同级 `AIPM-Data/` 目录（U 盘随行）
  - 支持 `AIPM_DATA_DIR` 环境变量覆盖（测试隔离用）
- 写入策略：配置修改即时原子替换并在失败时回滚；检测结果与告警运行态以 2 秒防抖保存，退出时等待通知交付并收尾。JSONL 历史按文件串行追加，查询和退出等待在途写入。

### 安全模型

- `contextIsolation: true` + `nodeIntegration: false`，渲染进程无法触达 Node API
- CSP：`default-src 'self'`，杜绝外部脚本注入
- API Key 仅存本地 JSON，界面传输已掩码，`publicProvider()` 序列化时剥离明文
- 所有渲染层插入点经过 `escapeHtml()` HTML 转义，防 XSS

## 技术特点

1. **轻量业务内核** — 网络与 JSONL 历史使用 Node 内置模块；运行依赖包括 electron-updater、https-proxy-agent、nodemailer 和 exceljs，邮件与 Excel 导出按需加载
2. **四态语义判定** — 在线、模型异常、离线与鉴权失败分别展示
3. **失败原因可解释** — 每个不可用模型都带人类可读原因，而非简单布尔
4. **格式自适应** — 同时兼容 OpenAI / Ollama / 数组三种模型列表响应
5. **精确变动检测** — 区分初始未知目录与已确认可用模型，轮询首次覆盖不误报新增；静默和失败交付后保留待发送事件
6. **可测试架构** — 模块冒烟、单元、缺陷回归和真实主进程集成测试覆盖检测/调度/通知/历史与页面路径；提供 `--smoke-test` 应用级自检
7. **便携部署** — Portable 版数据随 exe 目录走，即拷即用
8. **纯 Node 生成图标** — SDF 有符号距离场算法绘制圆角方块 + 心电折线，输出多尺寸 ICO（16/32/48/64/256），无图像处理依赖
9. **一致的 SVG 图标集** — 25+ 图标统一 24×24 viewBox / stroke 1.5 / round cap，常规 16px，导航 18px
10. **数据随行** — 单文件 JSON 存储，可直接备份/迁移/手工编辑

## 操作使用说明

### 1. 添加服务商

1. 切换到「服务商」页签，点击右上角 **新增服务商**
2. 选择适用模板（原生 Ollama 使用 `/api/tags` + `/api/chat`），然后填写：
   - **供应商名称**：如 `OpenAI` / `内部网关`
   - **URL**：API 根地址，如 `https://api.openai.com` 或 `http://192.168.1.100:3000`
   - **API Key**：服务方的密钥（本地 Ollama 等无鉴权服务可留空）
   - **轮循周期**：默认 5 分钟，数值 + 单位（秒/分/时/天/周/月/年）
   - **模型变化时上报**：开启后模型变动会推送通知
   - **备注**：可选
3. 高级配置可设置鉴权、端点、能力矩阵、断言、通知路由、维护、代理和服务商 SLO 目标；下方显示实际请求端点。保存和测试连接使用同一份有效配置。
4. 保存后立即纳入轮循；列表可启停、克隆。克隆副本保持停用，补充凭据后点击启用。

### 2. 手动检测

- **单个**：列表行右侧 ↻ 按钮
- **批量**：勾选多个 → 工具栏「检测」按钮
- **全部**：菜单栏 文件 → 立即检测全部（或 `Ctrl+R`）、仪表盘右上角「检测全部」、托盘菜单「立即检测全部」

### 3. 批量管理

- **全选 / 取消全选**：工具栏三态勾选框，仅操作当前筛选结果
- 批量删除与批量检测都作用于当前勾选集合，删除需二次确认
- 搜索框支持名称 / URL / 备注 模糊过滤（全选仅作用于筛选可见项）

### 4. 查看模型详情

- 点击列表中服务商**名称**，或**双击行任意位置**、双击仪表盘最近检测条目
- 弹窗中：绿色标签为可用模型，红色条目为不可用模型及其失败原因；点击任意模型名复制到剪贴板

### 5. 配置微信通知（企业微信群机器人）

1. 在 PC 端微信打开一个**企业微信群**（没有可自行创建内部群）
2. 群右上角 **「…」→ 群机器人 → 添加机器人**，创建并命名（如「状态监控」）
3. 复制弹出的 Webhook 地址（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx`）
4. 粘贴到 通知 → 微信 → Webhook 地址，打开开关，点击 **发送测试消息** 验证

### 6. 配置 QQ 通知（OneBot v11）

1. 准备一个 QQ 小号作为机器人，部署任一 OneBot v11 实现：
   - [NapCat](https://github.com/NapNeko/NapCatQQ)（推荐，Windows 友好）
   - [Lagrange.OneBot](https://github.com/LagrangeDev/Lagrange.Core)
   - go-cqhttp（已停维护但仍可用）
2. 在机器人端**开启 HTTP 服务端**（NapCat `servers.httpServers` / go-cqhttp `servers.http`），监听端口默认 `5700`
3. 机器人配置了 `access_token` 的话，同步填入程序「Access Token」栏
4. 程序内填写：**机器人 HTTP 服务地址**（如 `http://127.0.0.1:5700`）、**上报目标**（QQ 号或群号）、**上报类型**（私聊/群聊）
5. 打开开关，点击 **发送测试消息** 验证

### 7. 配置钉钉通知（自定义机器人）

1. 钉钉群 → 群设置 **「…」→ 机器人 → 添加机器人 → 自定义（通过 Webhook 接入）**
2. 安全设置三选一（推荐**加签**）：
   - **加签**：复制 `SEC` 开头密钥填入程序「加签密钥 SECRET」栏
   - **自定义关键词**：填入 `监控`（本程序消息标题含该词，直接命中）
   - **IP 地址段**：填写本机公网 IP
3. 复制 Webhook 地址（形如 `https://oapi.dingtalk.com/robot/send?access_token=xxxx`）
4. 粘贴到 通知 → 钉钉 → Webhook 地址，打开开关，点击 **发送测试消息** 验证

> 三种通知通道相互独立，可同时启用；某通道故障不影响其它通道推送。服务商必须单独打开「模型变化时上报」开关才会推送。

### 8. 检测选项（设置页签）

- **启动时自动开始检测**：应用启动即按各服务商周期开始轮循
- **并发检测数**：同时检测的服务商数量上限（1–16），服务商多且周期短时可调大
- **点击关闭按钮时**：隐藏到托盘（默认，后台继续监控）或直接退出程序

### 9. 日志

- 切换到「日志」页签实时查看运行日志，右上角可按级别 / 按服务商 / 关键字过滤、关闭自动滚动、清除日志、打开日志目录
- 「清除」仅清空界面显示，磁盘日志文件保留；底部「日志文件」卡片可删除单个磁盘文件
- 日志文件按天滚动：`%APPDATA%/ai-provider-monitor/logs/aipm-YYYYMMDD.log`

### 10. 托盘与退出

- 点击窗口 ✕ 的行为由 设置 → 点击关闭按钮时 决定：默认隐藏到系统托盘（后台持续轮循），托盘双击或右键「显示主界面」恢复
- 托盘右键菜单：显示主界面 / 立即检测全部 / 暂停检测（勾选）/ 逐服务商状态（点击直达详情）/ 退出
- 真正退出：托盘右键 → 退出，或菜单 文件 → 退出（`Ctrl+Q`）；若关闭行为设为「退出程序」，点 ✕ 即退出

## 常见问题

**Q: 检测显示「在线」但可用模型为 0？**
状态为「异常（degraded）」：服务本身可达、能返回模型列表，但所有模型探测失败。展开详情查看每个模型的具体原因（最常见是 API Key 无权限或额度耗尽）。

**Q: 探测会影响服务商计费吗？**
每轮对每个模型发送一次 `max_tokens=1` 的最小请求，消耗极小。模型很多时可以把探测方式设为仅列表，或使用默认单轮上限 20 并开启轮询覆盖。

**Q: 通知收到了但钉钉提示 sign not match？**
「加签密钥 SECRET」与服务商机器人安全设置中的密钥不一致，或机器人实际使用的是关键词/IP 白名单校验却误填了密钥栏。两种校验方式二选一。

**Q: QQ 测试消息失败 retcode=xxx？**
确认 OneBot 实现的 HTTP 服务已开启且端口正确；`access_token` 两端一致；上报目标 QQ 号/群号正确且机器人有权限发送。

**Q: 通道已经启用了，为什么健康面板还显示「未使用」？**
1.4.0 起面板按「开关 + 配置完整性」判定：开关打开但没填 Webhook / Token / 目标会显示「配置不完整」，配置完整但还没发过消息显示「已启用 · 待发送」。点该通道的「测试」按钮即可看到结果，成功后立刻变绿。1.3.x 及更早版本只认发送记录且不落盘，重启后会退回「未使用」，升级到 1.4.0 即可。

**Q: 关闭窗口后程序还在运行？**
默认行为——关闭隐藏到托盘，后台轮循继续。可在 设置 → 点击关闭按钮时 改为「退出程序」；随时可通过托盘菜单或 `Ctrl+Q` 退出。

**Q: 数据备份与迁移？**
复制 `%APPDATA%/ai-provider-monitor/` 整个目录（便携版为 exe 同级 `AIPM-Data/`），包含全部配置与日志。
